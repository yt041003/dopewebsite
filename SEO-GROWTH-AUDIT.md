# SEO growth audit — 2026-09-10

Baseline commit: 6fe73ff. Audit captured before growth implementation. Live sitemap and server HTML inspected for all 68 existing localized URLs. Text counts include navigation; they are descriptive, not quality scores.

## Technical

Next.js 16.3.3 App Router, React 19.2.6, TypeScript. Localized static generation with explicit quiz routes and a content registry/catch-all. Article content, H1, metadata and links are server-rendered. Client hydration is confined to quiz/space/interactive components; no pagination or site search. Two actual locale variants (zh-hant/en), reciprocal zh-Hant/en/x-default, self canonicals on production domain. Root, trailing slash, www and legacy deployment redirects are present. Query strings do not create new content; clean canonicals. Personalized results are client state, no result-session URLs or indexable score variants. Unknown routes return 404/noindex. Preview metadata and headers noindex. robots allows assets/public pages, disallows API; API has noindex header. Registry-driven sitemap excludes nonindex pages and APIs. No synthetic lastmod.

Unique title/H1/description and Open Graph/Twitter checked in prior full live regression. Central Organization/WebSite/WebPage/BreadcrumbList and Article schema are consistent with visible content. Supplied Twynzo icon remains the favicon. System fonts avoid remote font blocking; SVG/Next Image dimensions stabilize images. Large original icon remains for branding/social; do not replace supplied artwork. Canvas imports delayed 500ms, mobile particles reduced, 20fps renders, hidden-tab pause; rAF still wakes at display rate, and constrained device/save-data handling can improve. Reduced-motion skips initial canvas; HTML content never waits for Three.js. Mobile previously checked at 390px; new UI needs 360/390/768 checks. No field CWV evidence acquired: do not claim performance targets achieved.

## Findings and priorities

- P0: no known crawl blocker in baseline; rerun full route/metadata validation after changes.
- P1: type profiles have seven useful sections but lack dedicated conflict, decision and social examples. DOPE lacks explicit decision/stress sections. Love introduction could explain emotional expression and expectations more clearly.
- P1: quiz starts immediately, validated scoring/ties and PNG export preserved. 16-type results link to profiles; DOPE results do not contextualize leader links. Love results need onward reading. Related tests are distant from results.
- P2: content links to quizzes only at the bottom; add visible, purpose-specific calls to action while keeping body useful. Existing guides need a small relationship pillar, not dozens of pair pages.
- P2: native sharing and clipboard exist; add explicit social destinations without sending answers. No analytics SDK/framework detected in app/components/lib/package: do not install tracking or claim events collected.
- P2: HTML-first content, system fonts and delayed canvas are strengths; reduce unnecessary animation scheduling and support constrained devices.
- P3: only Stripe donation link exists, not report billing. No ads, affiliate or premium interfaces; prepare opt-in insertion points without publishing fake offers. Compatibility needs a private model, not 256 indexable pair pages.

## Product funnel

Search → indexable landing/guide → quiz is functional. First question is above SEO reading and no signup/paywall. Back/next, localization transfer and tied scores are supported. Completion uses anonymous deduplication; raw answers are not persisted server-side. Result PNGs have brand and concise results. Single personality shares use stable type URLs; DOPE/love share clean quiz URLs. No personal sessions in sitemap. Main gaps: obvious content-to-quiz CTA, DOPE result-to-profile links, result-to-next-test discovery and dedicated relationship reading. Free results must stay intact.
